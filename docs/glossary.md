# Glossary

Common language keeps reviews clear across engineering, operations, security, and compliance.

| Term | Meaning |
|------|---------|
| Agent | A system that can reason about a goal and take actions through tools or workflows. |
| Agent loop | The repeated process of planning, acting, observing, and deciding whether to continue. |
| Context window | The maximum prompt and conversation content a model can process in one request. |
| Evaluation | A repeatable test of model or agent behavior against expected outcomes. |
| Grounding | Supplying source data so generated output is based on approved context. |
| Human oversight | Required human review before or after AI-assisted decisions or actions. |
| Model drift | Behavior change caused by model updates, input distribution shifts, or system changes. |
| Prompt injection | Input that attempts to override instructions, exfiltrate data, or misuse tools. |
| RAG | Retrieval-augmented generation: retrieving external context before model generation. |
| Red team | Adversarial testing intended to expose safety, security, or policy failures. |
| Tool | A callable external capability, such as an API, database query, or file operation. |
| Tool fanout | The number of tool calls generated by one user request or agent task. |
| Trace | A record of model calls, prompts, completions, tool calls, and intermediate state. |

## Priority Terms

| Priority | Meaning |
|----------|---------|
| P0 | Critical requirement; production release should block without remediation or accepted exception. |
| P1 | High-impact requirement; should be completed before release unless explicitly accepted. |
| P2 | Important improvement; should be scheduled based on risk and capacity. |
| P3 | Useful refinement; can be handled opportunistically. |
